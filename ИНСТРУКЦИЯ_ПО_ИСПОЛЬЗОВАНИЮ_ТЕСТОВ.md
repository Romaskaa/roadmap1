## ?? Как использовать тесты

### Вариант 1: В Visual Studio (рекомендуется)

#### Шаг 1: Загрузить NuGet пакеты

```bash
# В консоли Package Manager Console (View ? Other Windows ? Package Manager Console)
Update-Package -Reinstall MSTest.TestFramework -Project newproj.Tests
```

#### Шаг 2: Запустить тесты

**Способ 1 - через Test Explorer:**
```
Test ? Test Explorer (Ctrl+E, T)
```
В окне Test Explorer видны все 86 тестов, готовых к запуску.

**Способ 2 - через меню:**
```
Test ? Run All Tests (Ctrl+R, A)
```

#### Шаг 3: Просмотреть результаты

- ? Зеленые тесты - прошли успешно
- ? Красные тесты - обнаружены ошибки
- ?? Пропущенные тесты - исключены из запуска

### Вариант 2: Из командной строки

```bash
# Сборка решения
dotnet build

# Запуск всех тестов
dotnet test

# Запуск тестов с подробным выводом
dotnet test --verbosity detailed

# Запуск конкретного набора тестов
dotnet test --filter "ClassName=RuleBuilderTests"
```

## ?? Ключевые особенности тестов

### ? Правильная структура
- **Arrange-Act-Assert (AAA)** паттерн
- **Clear naming conventions** - Test_Scenario_Expected
- **Single responsibility** - один тест проверяет одно

### ? Полное покрытие
- ? Happy path (идеальный сценарий)
- ? Edge cases (граничные случаи)
- ? Error conditions (обработка ошибок)
- ? Null validation (проверка на null)

### ? Использование MSTest Framework
- `[TestClass]` - маркер класса с тестами
- `[TestMethod]` - маркер метода теста
- `[TestInitialize]` - инициализация перед каждым тестом
- `[TestCleanup]` - очистка после каждого теста
- `[ExpectedException]` - проверка выбросов исключений

## ?? Анализ Builder Pattern

Подробный анализ соответствия кода паттерну Builder находится в файле:
?? **`АНАЛИЗ_ПАТТЕРНА_BUILDER_И_ТЕСТЫ.md`**

**Основные выводы:**
- ? RuleBuilder полностью соответствует паттерну Builder (9/10)
- ? Fluent Interface идеально реализован в CompositeRuleCondition (10/10)
- ?? ParseAnchor() нарушает принцип Open/Closed (требует улучшения)
- ?? Недостаточна валидация null элементов в collections

**Рекомендуемые улучшения:**
1. Использовать Dictionary для ParseAnchor() вместо цепи if
2. Добавить обработку null элементов в BuildCondition()
3. Применить Factory Pattern для большей гибкости
4. Добавить логирование для отладки
